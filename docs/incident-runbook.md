# 장애 대응 매뉴얼

자동 복구가 가능한 장애는 시스템이 재시도하고, 불가능한 장애는 관리자 알림(웹 알림 + 이메일)과 시스템 로그에 원인을 남깁니다.

| 상황 | 자동 처리 | 운영자 조치 |
| --- | --- | --- |
| 스마트폰 연결 끊김 | 2분 뒤 오프라인 표시·관리자 알림, 30분 뒤 대체 기기 배정 | 장애·유지보수에서 **ADB 재연결**, 케이블·전원 확인 |
| ADB 서버 오류 | 에이전트가 3회 실패 시 adb 서버 재시작 | 반복되면 제어 PC에서 `adb kill-server && adb start-server` |
| PC 에이전트 종료 | 서비스가 자동 재시작. 받은 작업은 임대 만료 후 회수되어 재시도 | 에이전트 로그(`agent.log`) 확인 |
| 인터넷 연결 끊김 | 에이전트가 결과를 로컬 보관, 지수 백오프로 재연결, 복구 후 동기화 | 관리 창 "전송 대기 건수" 확인 |
| 웹서버 재시작 | 일정·작업은 DB에 보존. 밀린 회차는 건너뛰고 다음 회차부터 진행 | Railway 배포 로그 확인 |
| 데이터베이스 연결 오류 | 연결 풀 재시도, 헬스체크 실패 시 Railway가 재시작 | Railway DB 상태 확인 |
| 검사 중 강제 종료 / 타임아웃 | 임대 만료(기본 30분) 후 회수 → 재시도(최대 3회, 60초·120초 백오프) → 초과 시 '수행 불가' 기록 + 고객 알림 | 작업 대기열에서 오류 확인 후 **재시도** |
| 앱 설치 실패 | 결과에 `INSTALL_FAILED_*` 사유를 실패로 기록(재시도 대상 아님) | 고객에게 minSdk·ABI·서명 확인 안내 |
| 앱 실행 실패 | 이후 단계는 '미수행'으로 기록, 크래시 로그 수집 | - |
| 파일 업로드 실패 | 스크린샷은 SHA-256 불일치 시 거부 → 에이전트 재전송. 고객 APK는 화면에서 다시 시도 | 저장소 여유 공간 확인 |
| 결제 웹훅 중복 수신 | 이벤트 ID 유일 제약으로 1회만 처리 | - |
| 기기 과열 / 저장공간 부족 | 해당 기기에 작업을 보내지 않음, 장기화 시 대체 기기 | 냉각팬·기기 정리 후 유지보수 해제 |
| 스토리지 연결 오류 | 헬스체크에 `storage_writable` 표시, 보고서 생성 실패는 시스템 로그·관리자 알림 | Railway 볼륨 마운트(`/data`) 확인 |
| 가용 기기 부족 | 주문을 '기기 배정 대기'로 두고 20초마다 재시도, 고객·관리자 알림 | 기기 증설 또는 `limits.max_plans_per_device` 조정 |

## 점검 순서

1. `/api/health` 응답 → 관리자 > 서버·DB 상태
2. 통합 대시보드 상단 경고(결제 비활성, 실기기 없음, SMTP 미설정 등)
3. 장애·유지보수 → 시스템 로그(error) → 검사 작업 대기열(failed·timeout)
4. Railway 서비스 로그

## 보안 사고

- 에이전트 인증키 유출 의심: PC 에이전트 > **인증키 폐기** → 등록 코드 재발급
- 관리자 계정 의심: 회원·권한 관리에서 정지 + 비밀번호 초기화, 관리자 활동 기록 확인
- `SECRET_KEY` 유출: 새 값으로 교체(모든 세션 만료) 후 PG·SMTP·AI 키 재입력
