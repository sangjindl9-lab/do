# 백업 및 복구 설명서

## 무엇을 백업하나

| 대상 | 방법 |
| --- | --- |
| 데이터베이스 전체 | 관리자 > 시스템 설정 > 백업·복구 > **지금 백업** (JSON gzip, `/data/backups/`에 저장, 다운로드 가능) |
| 업로드 파일(APK·스크린샷·보고서) | Railway 볼륨 백업(서비스 > Volume > Backups) |
| DB 원본 수준 백업 | Railway PostgreSQL의 Backups 기능 또는 `pg_dump "$DATABASE_URL" > backup.sql` |

권장: 주 1회 이상 "지금 백업" 후 파일을 내려받아 다른 곳에 보관하고, Railway의 DB·볼륨 자동 백업을 켜 둡니다.

## 복구

1. 백업·복구 화면에서 대상 백업의 **복구** → 확인 문구 `RESTORE` 입력 (최고관리자만 가능)
2. 복구 직전 상태가 자동으로 한 번 더 백업됩니다(종류: 복구 직전 자동 백업).
3. 전체 테이블을 비우고 백업 시점 데이터로 되돌립니다. **백업 이후의 변경분은 사라집니다.**
4. 복구 후 다시 로그인합니다.

주의
- 백업 파일의 비밀 설정은 암호화된 상태입니다. 복구하는 서버의 `SECRET_KEY`(또는 `ENCRYPTION_KEY`)가 백업 당시와 같아야 PG·SMTP 키를 읽을 수 있습니다. 다르면 관리자 페이지에서 키를 다시 입력합니다.
- DB만 복구하면 그 이후 올라온 파일의 기록이 사라지고, 반대로 볼륨만 되돌리면 기록은 있는데 파일이 없을 수 있습니다. 같은 시점의 DB·볼륨 백업을 함께 쓰세요.

## 서버를 새로 만드는 경우

새 Railway 서비스에 같은 `SECRET_KEY`로 배포 → 볼륨에 백업 파일을 올리거나 `pg_dump` 파일을 `psql "$DATABASE_URL" < backup.sql`로 적재합니다.
