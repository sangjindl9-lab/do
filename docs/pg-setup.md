# PG 인증정보 등록설명서 (토스페이먼츠)

1. 토스페이먼츠 가맹 계약 후 개발자센터 <https://developers.tosspayments.com> > 내 개발정보 > **API 키**에서 클라이언트 키와 시크릿 키를 확인합니다. 결제창(API 개별 연동) 키를 사용합니다.
2. 관리자 페이지 > 결제관리 > **PG 설정**
   - Client Key, Secret Key 입력 → 저장 (Secret Key는 암호화 저장되며 다시 표시되지 않습니다)
   - 결제 모드: **테스트 모드**(`test_` 키) 선택 → **연동 시험**으로 인증 확인
3. 개발자센터 > 웹훅에 PG 설정 화면의 **Webhook URL**(`https://<주소>/api/payments/webhook/toss`)을 등록하고 이벤트 `PAYMENT_STATUS_CHANGED`를 선택합니다.
4. 테스트 모드에서 고객 계정으로 실제 주문 → 결제창 → 승인 → 주문 확정, 관리자 결제 현황에서 부분/전체 환불까지 확인합니다.
5. 이상이 없으면 `live_` 키를 입력하고 **운영 모드**로 전환합니다.

| 모드 | 동작 |
| --- | --- |
| 결제 비활성화 | 결제 불가(주문은 저장됨). 키 등록 전 기본값 |
| 모의 결제 환경 | PG 없이 전체 흐름 검증. 실제 금전 거래 없음, 모의 기기만 배정, 매출 집계 분리 |
| 테스트 모드 | 토스 테스트 키로 실제 결제창 연동(실결제 없음) |
| 운영 모드 | 실결제 |

## 구현 내용

- 결제 금액은 항상 서버의 주문 금액을 사용하고, 승인 요청 금액·PG 응답 금액·주문번호를 모두 대조합니다.
- 주문 행 잠금 + "주문당 결제 완료 1건" 유일 인덱스로 중복 결제를 막습니다.
- 웹훅은 내용을 믿지 않고 PG에 결제를 재조회해 동기화하며, 같은 이벤트는 한 번만 처리합니다.
- 환불은 토스 결제 취소 API(`/v1/payments/{paymentKey}/cancel`)를 호출하고 멱등 키로 이중 환불을 막습니다.

실제 가맹점 키가 필요한 승인·취소·웹훅 왕복은 **외부 연동 대기** 항목입니다(요청 형식은 자동화 테스트로 검증).
다른 PG사는 `backend/app/services/payment_providers.py`의 `PaymentProvider` 인터페이스(confirm / fetch / cancel)를 구현해 추가합니다.
